# 家庭练习伙伴：记忆与反馈边界

## 当前能力

页面调用 `getCoachFeedback(records)`，其中 `records` 是**最新记录在前**的数组；可沿用现有记录格式 `{ route, accuracy, speed, date, title }`。新的记录可以带 `metric`：`key-press` 为按键正确率，`final-text` 为最终文本准确率，旧记录未标记时默认为 `final-text`。键盘考核还可附带 `mistakes: { a: 2, j: 1 }`。支持的路线是 `keyboard`、`pinyin`、`wubi`，准确率应为 0–100 的数字。模块返回：

```js
{
  mode: '本地规则反馈（未接入 AI 模型）',
  observation: '...',
  memory: '...',
  feedback: '...',
  recommendation: { route: 'keyboard', text: '...' },
  dataPoints: 4
}
```

观察、记忆、建议和兜底是**代码中的本地规则阶段**，并非模型或远程智能体。观察阶段筛选有效成绩，选择最新练习的路线和统计口径，查看其最近最多三次成绩；记忆阶段只比较同路线、同口径的成绩，且在符合条件的成绩达到四次时，对比最近两次与之前两次。不会对不同路线、不同口径的成绩求平均或进行高低比较。按键记录如果包含 `completion`（0–100）与 `timedOut`（超时题数），显示最新挑战完成率和超时情况；完成率低于 80% 时优先建议无计时练习，即使按键正确率很高也不因此给出过度肯定。建议当前路线；针对键盘薄弱键时，最多汇总最近五次键盘成绩附带的错键统计，其中包含键盘考核记录；只接受英文字母和正数。记录缺失或无效时退回键盘基础。少量样本的建议仅作练习参考，不能作为能力定级。

模块本身不写入存储也不联网；原有页面把练习记录保存在当前浏览器的本地存储，因此不同设备不会同步，清空浏览器数据或页面记录会删除本机历史。页面使用反馈时应展示 `mode`，不得称为真实 AI 智能体。若页面增加键位统计，应仅保存各键的错误次数，不保存用户输入的文字、实时键盘事件流或身份信息。清空练习记录也应清空以其派生的所有记忆（目前无独立记忆）。

## 将来接入模型的建议契约（尚未实现）

- 家长明确选择启用后，页面发送最少的汇总数据，经受控后端请求模型：例如路线标识、每路线近三次准确率、变化幅度、少量高频错误键的计数。不要上传姓名、年龄精确值、原始输入内容、逐键事件、聊天记录、账号标识或个人联系方式。
- 服务端校验白名单、取值范围、请求频次和长度，凭据只放服务端。选择实际服务前须确定未成年人数据处理政策、存储时限、删除机制、地域和成本。
- 可以将模型请求组织为“观察结果 → 历史比较 → 练习建议 → 安全检查”的工作流；模型输出限定为结构化字段，例如 `{ feedback, recommendedRoute }`，路线必须来自预设枚举，文字必须符合长度和适龄规则。
- 模型和题目内容均为不可信数据，不允许它调用任意工具或执行用户提供的指令；输出经后端校验与适龄过滤，失败、超时、不可用时回退上述本地反馈，不阻断练习。
- 接入前通过适龄内容评测、错误与延迟测试、可解释性和隐私审查；在界面显示处理方式，并允许关闭联网辅导与删除相关数据。
